# 簡易開発 手順2: コード修正

作成日時: 2026-05-19 08:03:22

## 目的

  手順1で承認された修正内容の要件に基づき、コードを修正します。
  修正前に、実装可能な内容であることを再確認します。
  既存仕様、既存ロジック、既存ID体系を不要に変更しないようにします。
  仕様書を作成、変更、削除してはいけません。
  修正中に仕様変更の必要性が判明した場合は作業を停止し、通常開発へ切り替えるかユーザへ確認して下さい。
  ユーザが承認した場合のみ、通常開発を手順1から開始して下さい。

## 参照ルール

  - `.rules/rules_common.md`
  - `.rules/dev/rules_dev.md`
  - `.rules/dev/quick_fix/rules_quick_fix_1_request.md`
  - `.rules/dev/quick_fix/rules_quick_fix_2_code.md`
  - 手順1で承認済みの `{filename}_v{n}.{m}_1_request.md`

## 入力

  - 手順1で承認済みの修正内容の要件
  - 修正対象のコードファイル
  - 直前バージョンまたは直前リビジョンのコードファイル
  - 必要に応じて既存仕様書

## 出力

  `{filename}_v{n}.{m}.{code_ext}`

## 作成内容

  以下を実施します。

  - 修正対象ファイルを確認する
  - 修正対象箇所を確認する
  - 実装可能な内容であることを確認する
  - 手順1で承認された範囲内でコードを修正する
  - 修正範囲外のコードを変更しない
  - 既存の `[KEEP]` ロジックを変更しない
  - 必要に応じてコメントを更新する
  - 必要に応じてログ出力を更新する

## 実装前確認

  コード修正前に、以下を確認します。

  - 手順1の成果物が承認済みであること
  - 修正内容が手順1の範囲内であること
  - 修正対象ファイルが最新であること
  - 修正対象箇所が特定できていること
  - 実装可能な内容であること
  - 動作確認方法が定義されていること

## 修正時の制約

  以下を守ります。

  - 指示されていない機能追加を行わない
  - 指示されていないリファクタリングを行わない
  - 指示されていないファイルを変更しない
  - 既存の入出力仕様を不要に変更しない
  - 既存の処理フローを不要に変更しない
  - 既存のID体系を不要に変更しない
  - 既存の `[KEEP]` ロジックを変更しない
  - 修正理由を説明できない変更を行わない

## 通常開発へ切り替える条件

  コード修正中に以下が判明した場合は、作業を停止し、ユーザに報告します。

  - 手順1の範囲を超える修正が必要な場合
  - 仕様変更または仕様書の修正が必要な場合
  - 基本設計または詳細設計の変更が必要な場合
  - 複数機能に大きく影響する場合
  - 入力仕様、出力仕様、DB仕様、ファイル仕様が変わる場合
  - 既存の `[KEEP]` ロジックに影響する場合
  - 実装可能な内容であることを確認できない場合

## 注意事項

  - 作業開始前に、参照ルールと参照ファイルを提示すること。
  - 修正前に、修正対象ファイルが最新であることを確認すること。
  - 実装可能な内容であることを確認すること。
  - 不明点や矛盾がある場合は作業を停止し、ユーザに確認すること。
