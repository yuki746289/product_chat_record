# 性能最適化 実行チェックリスト（v13・コピーして案件ごとに記入）

**判定方法:** 各項目を [x] / [ ] とし、証拠を残す。対象外は `N/A（理由）`、未確認は `UNVERIFIED` と明記。未確認・不一致を含むのに最終PASSとしてはいけない。

## メタデータ
- 対象案件／処理：
- 作業区分（分析 / batch / app / quick_fix）：
- 担当者／確認日／承認範囲：
- 対象Private/Publicリポジトリとブランチ：
- 固定commit SHA／データSHA256／母集団（行・銘柄・期間）：
- 既存成功artifact／再利用対象：
- 計測環境（CPU、RAM、Python、pandas/NumPy/Polars等、スレッド数）：
- 証拠（URL、Run ID、監査JSON）：

## 1. 事前分析
- [ ] O01 現行の入力・出力・数値計算条件・条件ID・非変更領域を固定
- [ ] O02 既成功artifact・チェックポイント・再実行禁止条件を列挙
- [ ] O03 現状の各stage計測（入力、前処理、演算、書出、ピークRSS）または未計測を明示
- [ ] O04 プロファイルでボトルネックと計算の重複・コピー回数を特定
- [ ] O05 目標（時間・メモリ・タイムアウト余裕）と合否基準を事前確定
- [ ] O06 作業権限／Actionsゲート／秘匿データの出力先を確認

## 2. 候補比較
- [ ] O07 pandas継続・改善案（不要ループ、groupby、copy、I/O）の適否を記録
- [ ] O08 NumPy案（配列化、マスク、bincount、共有キャッシュ）の適否を記録
- [ ] O09 Polars案（lazy、列選択、group_by、null処理）の適否を記録
- [ ] O10 追加ライブラリ採否と依存・環境リスクを記録（対象外はN/A）
- [ ] O11 同一入力・同一条件・同一環境で候補を比較（N/A理由可）
- [ ] O12 代表データで独立3回以上測定、中央値/ばらつき/ピークRSSを記録
- [ ] O13 採用理由を数値で説明、マイクロベンチだけで全体高速化を断言しない

## 3. 正しさの保護
- [ ] O14 保存元SHA、入力行数・銘柄・期間が一致
- [ ] O15 キー一意・件数・列名/順序・条件ID・順序契約を検証
- [ ] O16 全対象で非数値列、null/NaN/inf/0件/境界値を検証
- [ ] O17 全対象で数値許容誤差を事前固定し、キー/列単位で比較
- [ ] O18 未来データ混入・売買ロジック・特徴量・判定条件の非変更を確認
- [ ] O19 認証範囲（小標本、代表、全件、新Producer）の区別と不足を記録
- [ ] O20 旧成果物コピーのSHA PASSを新計算PASSにすり替えていない

## 4. 実行・運用
- [ ] O21 45分超・実測60%超・既timeout・分割可能性を評価
- [ ] O22 分割stage/shard境界、manifest、SHA、欠落・重複、成功条件を設計
- [ ] O23 完了したjob/artifactを再実行せず、失敗stageだけ再開可能
- [ ] O24 全jobに適切なtimeout/資源・並列上限・進捗出力を設定
- [ ] O25 public/private分離、ログ/キャッシュ/artifactの機微情報漏えいがない
- [ ] O26 原本・Production・完成済みCSV/HTMLの不変と一時stage削除を確認
- [ ] O27 本番merge/deploy等の未承認操作を行っていない

## 5. 最終判定
- [ ] O28 本番相当の全件同値（必要ならHTML/UI）を独立検証
- [ ] O29 旧/新処理時間・RAM・成功率と目標達成を実測で報告
- [ ] O30 正式結果をPASS / 限定PASS / FAIL / BLOCKEDのいずれかで記録
- [ ] O31 NG/UNVERIFIED件数、未決の承認・後続工程・引継ぎ位置を記録
- [ ] O32 監査ファイル、ベンチマーク、実測証拠と対象差分をGitに保存
