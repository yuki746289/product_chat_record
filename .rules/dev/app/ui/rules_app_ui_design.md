# UIデザイン追加ルール

## 1. 目的

参照画像、モックアップ、ワイヤーフレームまたは既存画面を基準とするUI開発で、機能だけを維持して見た目の要件を縮小することを防ぎます。

## 2. 適用条件

次のいずれかに該当する場合、通常開発の`app`に追加分類`ui-design`を適用して下さい。

- 参照画像、モックアップまたはワイヤーフレームが提示されている。
- HTML、CSS、画面構造、ブランド表現、キャラクター配置またはレスポンシブ構造を変更する。
- ユーザが参照画面との一致、再現またはデザイン変更を求めている。

単一プロパティ、文言または表示・非表示だけを変更し、仕様と画面構造を変更しない場合は`quick_fix`を使用できます。ただし参照画像との再現度が完了条件に含まれる場合は`ui-design`を使用して下さい。

## 3. 開始時の宣言

作業開始時に次を記録して下さい。

- 開発種類: `app`
- 追加分類: `ui-design`
- 参照資料のパスまたはURL
- 再現度: A / B / C
- 対象画面と対象外画面

|再現度|意味|許容される差異|
|---|---|---|
|A|高再現|実データ、利用可能素材および既存機能による不可避な差異だけを許容する。|
|B|構造再現|情報階層、主要配置、視線誘導、相対寸法およびレスポンシブ構造を再現し、装飾の軽微な差異を許容する。|
|C|参考|配色や雰囲気だけを参考にし、構造の変更を許容する。|

再現度が未指定で実装結果を大きく左右する場合はユーザへ確認して下さい。参照資料同士または既存仕様と矛盾する場合も、独自に縮小解釈せず作業を停止して下さい。

## 4. 機能維持とレイアウト維持

「既存機能を変更しない」は、既存処理、URL、データ構造および操作結果を維持する指示です。参照画像で要求されたDOM順序、情報階層、主要配置または外観を維持しなくてよいという意味ではありません。

次を別々に判定して下さい。

- 機能・データ・URLの維持
- DOM・レイアウト・視覚表現の変更
- 既存機能回帰の有無
- 参照資料との視覚差異

## 5. 参照資料の要素分解

要件定義前に、参照資料を次の表へ分解して下さい。参照画像が複数ある場合は画像ごとに識別子を付けて下さい。

|UI要件ID|参照位置|期待する要素・配置|現状|変更区分|必要素材|許容差異|確認方法|
|---|---|---|---|---|---|---|---|
|UI001|例: ホーム上部|例: 主見出し、説明、人物画像、CTAを一体化したヒーロー|未対応|ADD / MOD / KEEP / DEL|画像、アイコン|再現度に従う|画面幅別スクリーンショット|

次を必ず確認して下さい。

- 画面全体の情報階層
- ヘッダ、ヒーロー、本文、CTA、カード、フォーム、フッタの順序
- 文字、画像、余白、枠、背景および装飾の相対的な大きさ
- PCとモバイルでの並び替え、縮小、非表示および折り返し
- 参照画像にだけ存在する機能を追加するか、表示だけ再現するか
- 既存画面にだけ存在する機能をどこへ保持するか

## 6. 素材実現性確認

基本設計前に必要素材を棚卸しして下さい。

- 既存素材のパス、解像度、透過、トリミング可否
- 新規作成が必要な素材
- ライセンスまたは利用制限
- 参照画像どおりに再現できない要素と代替案

素材不足のまま、参照画像の主要構造を別デザインへ置き換えて実装を進めてはいけません。

## 7. 基本設計とプレビュー承認

基本設計には、画面単位のレイアウト図、DOMの大区分、PC・モバイルの配置、共通コンポーネント、既存機能の配置先およびUI要件IDを記載して下さい。

独自レイアウトまたは主要画面種別ごとに、実装前プレビューを作成して下さい。プレビューは静的HTML、画像または既存コードを使用しない確認用画面で構いません。

手順5の完了条件に、次を追加します。

- ユーザがプレビューを確認している。
- 参照資料との主要差異が説明され、承認されている。
- 未承認の主要差異が0件である。

承認前に詳細設計または本実装へ進んではいけません。

## 8. 詳細設計

詳細設計には次を記載して下さい。

- UI要件IDと対象HTML、CSS、JavaScript、画像の対応
- DOM順序と主要クラス名
- PCとモバイルの表示条件
- 主要寸法、相対寸法、余白、重なり順および画像トリミング
- hover、focus、active、展開・縮小状態
- 既存機能を保持する配置とイベント
- 実装しない参照要素と理由
- 画面幅別の確認方法

## 9. 実装開始前確認

実装前に、参照資料、再現度、要素分解表、承認済みプレビュー、詳細設計および素材が揃っていることを確認して下さい。要件を「共通ガイドを追加する」など一部分だけへ縮小してはいけません。

## 10. 画面確認

実装後は実際のアプリケーション画面で確認して下さい。静的プレビューだけで完了してはいけません。

最低限、次を確認して下さい。

- 指定された全画面幅
- 横スクロール、重なり、はみ出し、トリミング
- 主要な情報階層と視線誘導
- CTA、フォーム、フィルタ、地図操作部品等との衝突
- hover、focus、active、展開・縮小状態
- 既存機能回帰
- 参照資料との並列比較または注記付き比較

「横スクロールがない」「機能が動く」だけで視覚確認を合格にしてはいけません。

## 11. 完了条件

次を全て満たした場合だけ完了できます。

- 全UI要件IDが実装済み、承認済み差異または対象外として説明されている。
- 未承認の視覚差異が0件である。
- 画面幅別スクリーンショットが保存されている。
- 参照資料との比較結果が記録されている。
- 既存機能回帰がない。
- ユーザが最終画面を目視確認し、承認している。
